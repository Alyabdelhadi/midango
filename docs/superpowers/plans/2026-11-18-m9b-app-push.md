# M9b Push in the App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Android app receives the server's "Still coming?" reminders through Firebase Cloud Messaging and opens the booking when one is tapped.

**Context:** M9a built the server side: `PUT /me/devices { token, platform: "android"|"ios"|"web", language: "en"|"ar" }` (204), `DELETE /me/devices?token=…` (204, only the owner's), and `ReminderService` sends `notification { title, body }` + `data { bookingId }` through `FcmPushSender` (now active: the Admin SDK key is configured). Firebase project `yallaplay-a00a3`; the Android app `com.midango.midango` is registered and `app/android/app/google-services.json` is in place (untracked so far — it holds only public client identifiers and is meant to be committed).

**Design:**
- **Android only for now.** Firebase is initialised only when `!kIsWeb && Platform.isAndroid`; on web and iOS the push code is a no-op (iOS needs an APNs key; web needs a VAPID key and a service worker — both later). No `firebase_options.dart`: Android reads `google-services.json` through the Google Services Gradle plugin.
- **Permission** is asked once, right after the customer's first successful booking (on the confirmation page), not at launch. Android 13+ shows the system prompt via `FirebaseMessaging.requestPermission()`. A denial is remembered (no re-asking); Profile shows nothing extra.
- **Registration:** when signed in **and** permission is granted, get the token and `PUT /me/devices` with the app language. Re-register on: app start (signed in), sign-in, `onTokenRefresh`, and app-language change. Failures are silent (retried next start).
- **Sign-out:** `DELETE /me/devices?token=…` *before* clearing the session (needs the access token), then `deleteToken()`. Failures don't block sign-out.
- **Taps:** `getInitialMessage()` (app was closed) and `onMessageOpened` (app in background) → if `data.bookingId` is present, switch to the Bookings tab and push `BookingDetailPage` for that booking (load it from `/me/bookings` by id; if not found, just show the Bookings tab).
- **Foreground:** Android doesn't show a notification while the app is open, so `onMessage` shows a SnackBar with the title + body and a "View" action that does the same as a tap.

- [ ] Add `firebase_core` and `firebase_messaging` with `flutter pub add` (latest compatible). Add the Google Services Gradle plugin: in `settings.gradle.kts` plugins `id("com.google.gms.google-services") version "<current 4.4.x>" apply false`, and `id("com.google.gms.google-services")` in `app/build.gradle.kts` plugins.
